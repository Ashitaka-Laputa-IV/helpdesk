# 英文 Query 测试报告

> 本文汇总「用英文提问」条件下的两组测试：检索链路基准、端到端 A/B 对比。
> 早前用中文提问得到的结论不成立（详见第 5 节），以本报告数据为准。

## 1. 测试环境

| 项 | 配置 |
|---|---|
| 对话模型 | `qwen3-4b-instruct` @ `127.0.0.1:9938` |
| 嵌入模型 | `bge-m3`（1024 维）@ `127.0.0.1:9931` |
| 重排模型 | `bge-reranker-v2-m3` @ `127.0.0.1:9932` |
| 语料 | `data/langchain-docs`，180 篇英文文档，5.6 MB |
| bm25 索引 | 6700 块（固定窗口 1000/200） |
| 向量索引 | Chroma 7008 块（RecursiveCharacterTextSplitter 1000/200） |
| 召回配置 | bm25 top-10 + 向量 top-15，去重后约 25 条候选 |
| 重排 | rerank 后取 top-5 |

## 2. 测试一：检索链路基准

### 2.1 评测集

`data/eval/queries.json`，由 `tests/build_eval_set.py` 生成，`seed=42`：

| 档位 | 构造方式 | 条数 |
|---|---|---|
| `title` | 文档 H1 标题当查询，正解为该文档 | 30 |
| `paraphrase` | 本地模型读「标题 + 中段内容」生成**英文口语问题**，正解仍是该文档 | 30 |

每条查询重复 3 次 → 每档 90 次采样。

> 语料是英文文档，查询必须用英文。跨语种（中文问英文库）测的是语言不匹配，不是检索能力。

### 2.2 指标

- `Recall@K`：正解文档是否进入该阶段 top-K（按文件路径判断）
- `MRR`：正解首次出现名次的倒数均值（1/rank）
- `候选池`：bm25 ∪ 向量的并集，rerank 的理论上限
- `不重排 top5`：直接取候选池前 5（bm25 在前、向量补位）——**偏向 bm25，偏悲观**
- `RRF top5`：只按名次做倒数排名融合，不花模型成本，是**公平的无重排基线**
- `rerank 去重 top5`：按文档去重后取前 5，避免同一文档的多个分块挤占名额

### 2.3 标题档（简单）

| 阶段 | 平均 | 中位 | P95 | Recall | MRR |
|---|---|---|---|---|---|
| bm25 top10 | 0.5ms | 0.5ms | 0.7ms | 96.7% | 0.625 |
| 向量 top15 | 12.2ms | 11.0ms | 17.1ms | 96.7% | 0.719 |
| 候选池 | — | — | — | **100%** | 0.626 |
| 不重排 top5 | — | — | — | 83.3% | 0.609 |
| RRF top5 | — | — | — | 96.7% | 0.786 |
| rerank top5 | **505.0ms** | 501.6ms | 582.9ms | 96.7% | **0.911** |

整条链路（串行）：平均 **518ms**。

### 2.4 改写档（困难，英文口语问题）

| 阶段 | 平均 | 中位 | P95 | Recall | MRR |
|---|---|---|---|---|---|
| bm25 top10 | 0.5ms | 0.5ms | 0.7ms | 83.3% | 0.553 |
| 向量 top15 | 14.8ms | 13.8ms | 23.3ms | **90.0%** | 0.679 |
| 候选池 | — | — | — | **93.3%** | 0.560 |
| 不重排 top5 | — | — | — | 63.3% | 0.528 |
| RRF top5 | — | — | — | 83.3% | 0.698 |
| rerank top5 | 565.9ms | 565.2ms | 659.8ms | 76.7% | 0.681 |
| rerank 去重 top5 | — | — | — | 80.0% | 0.696 |

整条链路（串行）：平均 **581ms**。

### 2.5 top-k 消融（改写档）

| top-k | RRF 召回 / MRR | rerank 召回 / MRR | rerank 去重 召回 / MRR |
|---|---|---|---|
| 5 | 83.3% / 0.698 | 76.7% / 0.681 | 80.0% / 0.696 |
| 8 | 90.0% / 0.709 | 80.0% / 0.686 | 90.0% / 0.709 |
| 10 | 90.0% / 0.709 | 83.3% / 0.689 | **93.3% / 0.713** |

## 3. 测试二：端到端 A/B 对比

### 3.1 被测对象

## 4. 结论

### 4.1 检索质量

1. **标题档掩盖差异**：bm25 / 向量 / rerank 全是 96.7%，只有 MRR 能看出排序差别（0.625 → 0.911）。
2. **英文改写档才分得开**：bm25 83.3% / 向量 90.0% / 候选池 93.3%。
3. **两路召回必须融合**：不重排基线（bm25 优先）仅 63.3%，同一候选池用 RRF 免费就能到 83.3%。
4. **rerank 净收益有限**：top-5 时 76.7%，**低于** RRF 的 83.3%；按文档去重也只到 80.0%；
   要到 top-10 且去重才反超（93.3% vs 90.0%，MRR 0.713 vs 0.709），代价 566ms 与更长上下文。
5. **同一文档的多个分块会挤占名额**：去重让 top-8 从 80.0% 提到 90.0%（+10 个百分点），零成本。
6. **rerank 成本在候选池、不在输出条数**：top-5 → top-10 只多 35ms。

### 4.2 端到端表现

1. **B 慢约一倍**：A 稳定 17~19s，B 29~37s。差距集中在第 2、3 轮——
   B 需要额外一次模型调用决定是否用工具，且回答明显更长（第 3 轮 12.5~14.8s vs A 6.5~7.0s）。
2. **检索判定各有各的错**：
   - A 每次都把第 4 轮「我刚才问过什么」误判成需要检索（稳定 5/6）；
   - B 大多能跳过，但第 4 次运行**漏检索**了第 2 轮（明确该查文档的没查）。
   - 一个偏多查，一个偏漏查，都不稳定正确。
3. **可控性**：A 多一次固定 router 调用（`max_tokens=128`，约 2s），行为可预测；
   B 的决策调用无 token 上限，可能先写一段再调工具，耗时与行为不固定。

## 5. 数据勘误：早前中文测试作废

早前用中文提问（"LangChain 里怎么定义一个工具？" 等）跑同一组对比，得到：

- A/B 总耗时都在 15~24s，B 一度**更快**（14.57s vs 16.63s）
- bm25 召回掉到 **26.7%**，向量 86.7%

问题在于**语料是英文文档**，中文查询与原文零字面重合，测到的是「语言不匹配」而不是检索能力。
改用英文后，bm25 回到 83.3%，B 也不再更快。**上表数据（第 2~4 节）为当前唯一有效结论。**

## 6. 复现命令

```bash
# 生成英文评测集（30 篇文档 → 标题档 + 改写档）
uv run python tests/build_eval_set.py --docs 30

# 检索链路基准
uv run python tests/benchmark_retrieval.py --eval-set data/eval/queries.json --tier title --repeat 3
uv run python tests/benchmark_retrieval.py --eval-set data/eval/queries.json --tier paraphrase --repeat 3 --top-k 10

# 端到端 A/B 对比（英文 6 轮语料，串行）
uv run python tests/compare_rag.py
```

## 7. 评测局限

- 改写档查询由本地 4B 模型生成，风格单一，不能代表全部真实提问。
- 正解按「文档」而非「片段」判定，粒度偏粗。
- 每档 30 条 × 3 次，约 ±3 个百分点的噪声；结论看趋势，不宜纠结单点数值。
- 端到端耗时受本地模型服务抖动影响较大（同一轮可有 2 倍波动），比较时应看多次运行的区间。
